手持ちの PDF や画像の zip を棚に並べて読む iOS アプリ [Tanabako](https://apps.apple.com/jp/app/tanabako/id6830099962) を、App Store に出しました。2026-10-31 に作り始め、11-03 に TestFlight で実機に入れ、11-04 に審査に出し、11-06 に日本で配信が始まりました。審査は差し戻しなしで 1 回で通りました。

実装も公開の準備も、大半は AI のコーディングエージェント (Claude Code) が進めました。人 (私) は、自分の情報が要る操作と、「審査に出す」のボタンと、実機での確認を受け持ちました。この記事では、その分け方と、使った道具と、途中でつまずいたことを書きます。

![公開の準備の分担。Claude Code は App Store Connect の入力、スクリーンショットの撮影と追加、ビルドの archive とアップロード、審査メモとビルドの選択、App のプライバシーの回答の案を受け持った。人はログイン、利用規約への同意、連絡先と DSA の申告、審査に出すボタン、TestFlight での実機の確認を受け持った。決めることは人が選び、Claude Code が入力した](/TIL/images/app-store-split-ja.svg)

## 作り始めてから審査に出すまでは 5 日だった

公開までの規模は次のとおりです。数えたのは、作り始めた 10-31 から審査に出した 11-04 までのアプリのリポジトリです。

| 項目 | 数 |
|---|---|
| コミット | 189 |
| マージした PR | 42 |
| テスト (Swift Testing) | 316 件 |

なお、配信を記録した 11-07 のコミットまで含めると 190 コミットです。同じ時点で、Backlog.md のタスクは 111 件、決定の記録は 11 件、設計などの文書は 3 件ありました。集計期間が違うため、上の 189 件とは区別しています。

コードは作業ブランチで進め、PR を開くと GitHub 上の Codex がレビューします。42 本すべてに Codex のレビューが付きました。指摘は Claude Code が 1 件ずつ確かめてから直し、マージまで進めます。

人が画面で確かめる作業は、まとめて行うことにしました。Claude Code は、タスクの実装が済んでテストが通ったら、人の確認を待たずにそのタスクを Done にします。人の確認は「確認: 〜」というタスクにいくつかまとめ、main にマージされたあとで、タスクに書かれた手順どおりに見ます。前に作っていたアプリでは、人が確かめて OK を出すまで次のタスクに進まない決まりでした。Tanabako では、この 1 点を最初に変えています。

## 使った道具

| 用途 | 道具 |
|---|---|
| 実装・調べ物・App Store Connect の操作 | Claude Code。全体を見るセッション 1 つが、実装や調べ物を別のエージェントに任せる |
| タスクと決定の記録 | Backlog.md (Markdown のファイルでタスクを持つ CLI) |
| コードレビュー | GitHub の PR と Codex |
| App Store Connect と Dropbox の画面の操作 | Claude in Chrome (Chrome の拡張から Claude Code がブラウザを操作する) |
| スクリーンショット | XCUITest と `xcrun simctl status_bar` |
| 審査用のビルドのアップロード | `xcodebuild archive` と `xcodebuild -exportArchive` |
| プライバシーポリシーとサポートのページ | GitHub Pages の公開リポジトリ |

タスクの記録をリポジトリの中に置いたのは、セッションが切れても次のセッションが同じところから続けられるようにするためです。App Store Connect に何を入れ、読み込み直して残っていたかどうかも、タスクのノートに書かせました。サポート窓口には GitHub Issues を使っています。

## 公開の準備は 7 つのタスクに分けた

TestFlight に出せた時点で「App Store で公開する」という親タスクを作り、準備を子タスクに分けました。

1. プライバシーポリシーとサポートのページを用意する
2. App のプライバシーの回答を決めて入れる
3. スクリーンショットをそろえる
4. 製品ページの文言・価格・年齢制限を決める
5. Dropbox のアプリを公開用にする
6. EU のデジタルサービス法 (DSA) のトレーダー申告をする
7. 審査に出す

子タスクごとに、人が決めることと、Claude Code が手を動かすことが違います。たとえば App のプライバシーは、Claude Code がコードと `PrivacyInfo.xcprivacy` を読んで、外へ出る通信を洗い出しました。外部サービスへの接続先は利用者自身の Dropbox だけで、解析やクラッシュ収集の SDK は入っていません。Wi-Fi 転送は端末上の `NWListener` による HTTP サーバーで、同じ LAN のブラウザからファイルを受け取ります。開発者にデータを送る仕組みはありません。そこから「データの収集なし」と答える案を出し、私が了承してから Claude Code が回答を公開しました。製品ページの文言は A/B/C の案から私が選び、Claude Code が入力しました。年齢制限の質問票は 7 段階すべて「なし」または「いいえ」となり、4+ でした。

スクリーンショットは UI テストで撮りました。iPhone Duo の閉じた画面と iPhone 18 Pro 向けに、それぞれ 5 枚用意しました。見本の本はテストのコードで作った自作のものだけにし、ステータスバーは `simctl status_bar` で 9:41 に固定しました。App Store Connect の案内によると、iPhone Duo のスクリーンショットを入れると、製品ページに Duo 向けのバッジが付きます。

## 外から見える操作と、自分の情報は人が受け持った

App Store Connect の操作は、どれを Claude Code に任せるかを先に決めておきました。

| Claude Code が受け持った | 人が受け持った |
|---|---|
| 文言・キーワード・カテゴリ・価格・配信する国の入力 | App Store Connect と Dropbox へのログイン |
| 年齢制限の質問票、App のプライバシーの回答 (中身は人が了承) | 利用規約への同意 |
| スクリーンショットのアップロード | App Review の連絡先、DSA の申告 |
| 審査メモの入力、ビルドの選択 | 「審査に出す」のボタン |
| ビルドの archive とアップロード | TestFlight での実機の確認 |

線を引いた理由は 2 つあります。1 つは、パスワード・連絡先・申告の中身のような自分の情報を AI に扱わせたくなかったことです。もう 1 つは、提出のように外に向けて状態が変わる操作は、自分の手で押したかったことです。Claude Code の自動モードも、審査に出す操作と、公開リポジトリへの push を止めました。サポートページの push は、Claude Code のプロンプトで `!` を付けて私が実行しました。

価格や配信する国のように Claude Code が入力するものでも、決めるのは人です。Claude Code は案と理由を出し、私が選んだものを入れます。

## つまずいたのは、Apple と Dropbox のアカウントまわりだった

コードよりも、アカウントや登録の状態で止まることが多くありました。

### バンドル ID が無料のチームで登録済みだったので、アプリ名ごと変えた

TestFlight に上げようとしたとき、最初の名前 (Gatefold) のバンドル ID は、以前に無料の開発チーム (Personal Team) で登録済みでした。有料のチームでは使えず、無料のチームの登録は消せません。公開前だったので、バンドル ID だけでなくアプリ名ごと Tanabako に変えました。名前の候補は、Claude Code が App Store や同名の製品、米国の商標を Web で調べてから出しました。

### Dropbox のアプリを、個人のアカウントで作り直した

Dropbox から本を取り込む機能のために、Dropbox の開発者向けの画面でアプリを作ってあります。公開の準備で表示名を直していたとき、そのアプリが個人ではないアカウントに作られていたと分かりました。個人のアカウントにアプリを作り直し、アプリに埋め込むキーを差し替えて、TestFlight のビルドで接続できることを確かめました。

Dropbox のアプリには「開発中」と「本番」があり、最初は本番への申請も準備に入れていました。申請の画面を読むと、開発中のままでも 500 人まで接続でき、審査はアプリが 50 人とつながるまで行われないと書いてありました。なので申請は出さずに公開し、接続した人数が 50 人に近づいたら申請することにしました。

### 日本だけで配信しても、DSA の申告は求められた

1.0 は日本だけで配信します。それでも App Store Connect には、EU の DSA に基づくトレーダーかどうかの申告が求められていました。申告するのは Apple Developer Program のアカウントの持ち主なので、私が入力しました。

### App Store Connect は、保存したつもりの値が残っていないことがある

Claude Code には、入力して保存したら必ずページを読み込み直し、値が残っていることを確かめるようにさせました。ページを移った直後は要素が見つからず、操作が失敗することもあります。そのときは少し待ってからページの文字を読み直させました。

## 審査メモには、ログインなしで試せる手順を書いた

Tanabako にはアカウントがなく、本のファイルを取り込まないと何も表示されません。審査の担当者が自分でファイルを用意しなくて済むように、サポートページに見本の PDF と zip を置きました。審査メモ (英語) には、Safari でそのページを開いてファイル App に保存し、アプリの「+」から取り込む手順を書きました。Dropbox との接続は審査には要らないことと、読むときは通信しないことも書いています。

審査に出してから 2 日ほどで通り、リリースを自動にしてあったので、そのまま配信が始まりました。

## 次のアプリのために、手順を Claude Code のスキルにした

公開まで通したあと、この流れを Claude Code のスキル (作業の手順を書いた Markdown のファイル) にまとめました。書いたのは次のことです。

- 子タスクの分け方
- Claude Code と人の分担
- App Store Connect の画面の場所と操作のこつ
- ビルドとアップロードのコマンド
- 審査メモの書き方
- リジェクトされたときの進め方

次に別のアプリを出すときは、「App Store に出したい」と言えば、Claude Code がこのスキルを読んでから始めます。

アップロードには注意が 1 つあります。ふだんの開発は β 版の Xcode で行っていますが、β 版でビルドしたものは App Store Connect に上げられません。上げるビルドだけは、`DEVELOPER_DIR` で正式版の Xcode を指定して作ります。これもスキルに書きました。輸出コンプライアンスの設定では、対象となる暗号化を使わないことを確認し、Info.plist の `ITSAppUsesNonExemptEncryption` を `NO` にしました。

今回は速さを優先して AI に大部分を任せました。公開後は実際に使いながら細部を調整し、英語対応と日本国外への配信も今後進める予定です。
